# PWA Simple Creator plugin for Kanboard

Turn your Kanboard into an **installable Progressive Web App (PWA)** on Windows 11, Android, and iOS.

Once the plugin is installed, users can add Kanboard to their desktop or home screen as if it were a native app: custom icon, standalone window without the browser bar, and direct access from the application launcher.

> **Note:** This plugin does not implement offline functionality. Kanboard requires a connection to your server just as usual — the difference is the seamless experience of having it as an installed app.

---

## Features

- ✅ **Native Settings**: Built-in configuration within the Kanboard interface
- ✅ **Color Modes**: Light, Dark, and Custom color themes
- ✅ **Start URL**: Open in the dashboard or a specific board by default
- ✅ **Custom Description**: Customize the installer prompt description
- ✅ Installable on **Windows 11** (Chrome, Edge)
- ✅ Installable on **Android** (Chrome)
- ✅ Automatic detection of the Kanboard base URL
- ✅ Standalone window (`standalone` mode)
- ✅ Splash screen with customizable colors
- ✅ Custom icon in the app launcher
- ✅ Support for iOS / Safari (Add to home screen)
- ✅ Compatible with subdirectories (`/kanboard/`, `/app/`, etc.)
- ✅ Compatible with reverse proxies and SSL termination
- ✅ **No File Permissions Needed**: Stores configuration natively in Kanboard's database

---

## Requirements

- Kanboard **1.2.x** or higher
- The server must serve Kanboard over **HTTPS** (required for PWA installation in production by modern browsers)
- Local development (`http://localhost`) is also supported

## Installation

1. Clone or copy the `PWASimpleCreator` folder to `<kanboard>/plugins/`:

   ```
   <kanboard>/
   └── plugins/
       └── PWASimpleCreator/          ← plugin folder
           ├── Plugin.php
           └── ...
   ```

2. Place your icons in `plugins/PWASimpleCreator/Asset/icons/`:
   - `icon-192.png` — 192 × 192 px (PNG, mandatory)
   - `icon-512.png` — 512 × 512 px (PNG, mandatory)

3. Go to **Kanboard → Settings → Plugins** and activate the plugin.

4. Open Kanboard in Chrome/Edge. You will see the install icon (⊕) in the address bar.

---

## Configuration

Configuration is done visually from the native Kanboard interface:

1. Go to **Kanboard → Settings → PWA Settings**.
2. Define the **App Name** and **Short Name** (if left empty, "Kanboard" will be used).
3. Set the **Description** for the installer.
4. Select your preferred **Color Mode** (Light, Dark, or Custom) to tint the window and the loading screen.
5. Optionally, define the **Start URL** (e.g., `board/1`).
6. Click Save.

*Data is stored securely in Kanboard's database using the native `ConfigModel`.*

│   ├── PwaConfigController.php    — Web settings interface logic

## How to install the app

### Windows 11 — Chrome / Edge

1. Open Kanboard in the browser.
2. Click the **⊕ Install** icon in the address bar (top right corner).
3. Confirm the installation.
4. Kanboard will appear in the Start menu and on the desktop.

### Android — Chrome

1. Open Kanboard in Chrome.
2. A **bottom banner** "Add Kanboard to Home screen" will appear.
   - If it doesn't appear: Menu (⋮) → **Add to Home screen**.
3. Kanboard will appear on your home screen like any other native app.

## Manifest Verification

You can verify that the manifest is being served correctly by opening the route generated by Kanboard, for example:

```
https://your-server/?controller=PwaManifestController&action=manifest&plugin=PWASimpleCreator
```
*(Or `/pwa/manifest` if Kanboard URL rewriting is enabled).*

You should see a JSON with `name`, `icons`, `start_url`, etc.

In Chrome DevTools → **Application → Manifest** you can inspect the loaded manifest and verify that there are no installability errors.

## FAQ

**Why is the manifest a Controller endpoint and not a static `.json`?**

Because it needs to dynamically read your settings from the database and automatically detect the Kanboard base URL to generate the `start_url`, `scope` and icon URLs correctly. It works whether Kanboard is in the root or a subdirectory.

**Why is there a Service Worker if there is no offline cache?**

Modern browsers (Chrome, Edge, Samsung Internet) require a Service Worker to be registered in order to show the install button. The included Service Worker is minimal: it does not cache anything and passes all requests directly to the network.

**Does it work with Kanboard behind a reverse proxy (nginx, Traefik, Caddy)?**

Yes, Kanboard's routing handles proxy setups smoothly.
